# Jira Service Management Help Desk Lab

## Project Overview

This project is a simulated IT help desk environment created using Jira Service Management. I built the lab to gain hands-on experience with ticket intake, incident management, prioritization, troubleshooting, escalation, technical documentation, and ticket resolution.

The tickets in this project represent common issues that an entry-level help desk or IT support technician may encounter.

## Objectives

The objectives of this project were to:

* Practice creating and managing IT support tickets
* Assign appropriate ticket priorities
* Document user-reported technical issues
* Record troubleshooting steps clearly
* Move tickets through the support lifecycle
* Write professional user updates and resolution notes
* Organize requests using queues, statuses, and ticket fields

## Tools Used

* Jira Service Management
* Windows 10/11 support concepts
* Microsoft 365 support concepts
* Basic networking troubleshooting
* Technical documentation
* Incident and request management workflows

## Ticket Workflow

The tickets were managed through different stages of the support process:

1. Open
2. In Progress
3. Waiting for Support
4. Waiting for Customer
5. Resolved

Each ticket included a description of the reported issue, an assigned priority, troubleshooting notes, status updates, and a final resolution when applicable.

## Issues Simulated

The lab includes support scenarios involving:

* Password resets
* Account lockouts
* Login problems
* Microsoft Outlook issues
* Printer connectivity
* Slow computer performance
* Wi-Fi and network connectivity
* Software installation requests
* Hardware and peripheral problems
* Microsoft 365 access
* Multi-factor authentication
* Shared drive access
* New-user onboarding

## Example Support Process

A typical ticket in this lab followed this process:

1. Review the user's reported issue
2. Categorize the request
3. Determine the appropriate priority
4. Record initial troubleshooting information
5. Move the ticket to In Progress
6. Document each troubleshooting action
7. Request additional information when necessary
8. Escalate issues outside the technician's access or scope
9. Confirm that the issue was resolved
10. Add resolution notes and close the ticket

## What I Learned

This project strengthened my understanding of how IT support teams organize, document, prioritize, and resolve technical issues. It also helped me practice communicating troubleshooting steps clearly and maintaining accurate ticket records throughout the support lifecycle.
